01 / HTML TO VIDEO

HTMLで短い動画をつくる

商品紹介、文字演出、SNS動画ならHTMLベースのHyperFramesが適しています。付属スキルで構成と実装を進め、プレビューしながら修正できます。

Opus 5.5→HyperFrames制作スキル→HTML + 時刻指定できる動き→Chrome + FFmpeg

選ぶ理由

HTML、CSS、画像、音声を一つのコンポジションにまとめられます。GSAP、Anime.js、Lottie、Three.js等との連携にも対応しています。

必要な環境

Node.js 22以上とFFmpegが必要です。ローカルでの書き出しに外部クレジットは不要です。外部APIや音声・画像生成を使う場合は別途認証が必要です。

導入の入口

プロジェクトを作り、プレビュー
npx hyperframes init motion-video
cd motion-video
npx hyperframes skills update
npx hyperframes preview

書き出しはnpx hyperframes render --output video.mp4を実行します。オプション詳細は--helpで確認できます。

HyperFrames固有のコンポジション属性とタイムライン登録規約に従います。HTML単体のwindow.seek(t)とは仕様が異なります。各ライブラリのライセンスも確認してください。

02 / REACT TO VIDEO

Reactで動画を組み立てる

テンプレート動画や字幕・数値の差し替えにはRemotionが適しています。公式Agent Skillsを使い、Reactコンポーネントとして画面を組み立てます。

Opus 5.5→Remotion Agent Skills→React + フレーム番号→Remotionの書き出し

動きの時間をそろえる

useCurrentFrame()とFPSから位置や色、カメラを決定します。実時間依存のアニメーションを使うと書き出し時にフレームのずれが生じます。

3Dや既存アニメーションを足す

3Dには@remotion/three、Lottieには@remotion/lottieなど、フレーム連動に対応した公式パッケージを利用できます。

導入の入口

公式の空テンプレートを使う
npx create-video@latest --yes --blank motion-video
cd motion-video
npx remotion skills add
npm run dev

Studioでプレビュー確認し、調整後に書き出します。既存プロジェクトへスキルを追加する場合はnpx skills add remotion-dev/skillsを実行します。

Remotionは独自ライセンスです。個人、小規模組織、非営利等向けの条件と、企業向けライセンス（Company License）の要件を確認して利用してください。

Opus 5.5 + 設計スキル→React / HTML→MotionまたはGSAP→Webで操作
表現入口選ぶときの視点
レイアウトの変化、ドラッグ、スプリングMotionReactとの接続、操作の途中で入力しても自然につながるか。
文字演出、複数要素の連動GSAP / Anime.js時刻と順番を管理できるか。GSAPの独自利用条件も確認。
立体、光、シェーダーThree.js / Fiber + Drei必要なGPU機能、Reactの有無、素材とカメラの扱い。
キャラクターの状態に応じた動きRive Runtimes制作済み.riv素材の有無、エディタ・素材・サービスの条件。

キーボード操作、prefers-reduced-motion、画面幅への対応を確認します。動画化する場合は、入力依存の動きを時刻から一意に決定できるように設計します。

THE PRODUCTION LOOP

良い指示を、見直せる制作へ。

素材、伝える内容、出力条件を整理し、シーン構成を実装して映像と音を確認・調整します。この一連の手順をスキルで効率化できます。

01伝えることを決める

目的、ターゲット、必須テキスト、出典、使用するロゴや素材。

02見た目と時間を決める

配色、フォント、解像度、フレームレート、シーン構成と遷移。

03フレームを確認する

キーフレーム、表示崩れ、文字切れ、レイヤーの重なり、アセット読み込み。

04通して視聴する

テンポ、トランジション、音声同期を確認し、最終書き出しを行います。

任意の時刻へ戻れる設計

HTML制作では、seek(t)で指定時刻の状態を計算します。フレーム番号をFPSで割って時刻を算出し、描画完了後にフレームを取得することで正確な動画化が可能です。

時間を基準にした状態の計算 / 独自の概念例
function stateAt(seconds) {
  const p = Math.max(0, Math.min(1, seconds / 0.8));
  const eased = 1 - Math.pow(1 - p, 3);
  return { opacity: eased, y: 40 * (1 - eased) };
}
// レンダラー側: seconds = frameNumber / fps
// ページ側: 状態を適用 → フォント・素材・描画完了 → 取得

乱数はseedを固定し、物理演算は任意時刻の状態を再現できるように実装します。setTimeoutや制御外のCSS transitionはフレームずれの原因になります。

DIRECT / RENDER / REFINE

動きを指定し、フレームで直す

「高級感」「もっと派手に」を、色・材質・移動量・時間へ置き換える。見せたい動きを決めてから、途中のフレームを見て仕上げます。

先に、見せ方を決める

目的、尺、サイズ、FPS、色、書体、場面ごとの主役を指定します。登場の速さ、弾み、要素間の遅れも数値にして、避けたい表現は具体名で伝えます。

同じ時刻を描き直せるようにする

位置や形をフレーム番号と時刻から決めます。フォントや素材の読み込みを待ち、乱数のseedも固定。ループは全N枚のうち0〜N−1を出力し、終端から冒頭へのつながりを確認します。

気になる動きの前後を見る

コンタクトシートで全体を見て、問題の前後を拡大します。「着地が2フレーム遅い」「文字を読む間は動きを止める」のように、場所と変更内容を絞って修正します。

音も、書き出した後に確かめる

映像のイベントと音のピークを照合し、音量やループ境界も確認します。Web Audioで効果音を合成する方法もあります。数値の検査に加え、完成した動画を視聴して判断します。

フレームを指定する修正ブリーフ
FPSと、動きが起きるフレーム番号を確認してください。
その前後の静止画と、場面全体のコンタクトシートを出してください。
見る点：主役の見やすさ、文字の読む時間、動きの順番、終端のつながり。
問題ごとに「フレーム番号・見える問題・変更する値」を挙げてください。
影響の大きい2点を修正し、同じフレームを再出力して比べてください。
