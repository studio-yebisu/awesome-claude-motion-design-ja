01 / HTML TO VIDEO

HTMLで短い動画をつくる

商品紹介、文字演出、図形を使うSNS動画なら、HTMLをソースにできるHyperFramesが入口になります。付属スキルで構成と制作を進め、プレビューを見ながら修正します。

Opus 5.5→HyperFrames制作スキル→HTML + 時刻指定できる動き→Chrome + FFmpeg

選ぶ理由

HTML、CSS、画像、音声を一つのコンポジションにできます。GSAP、Anime.js、Lottie、Three.js等との連携も公式が案内。HTMLの制作環境を使い続けたい場合に向きます。

必要な環境

公式READMEの要件はNode.js 22以上とFFmpeg。ローカル書き出しはHeyGenクレジットを使いません。外部の音声・画像生成やクラウドは、それぞれの費用と認証が必要です。

導入の入口

プロジェクトを作り、プレビュー
npx hyperframes init motion-video
cd motion-video
npx hyperframes skills update
npx hyperframes preview

制作後はnpx hyperframes render --output video.mp4で書き出し。導入した版の--helpで利用できるオプションを確認できます。

HyperFramesのコンポジション属性とタイムラインの登録規約に従います。独立したHTMLのwindow.seek(t)とは別の契約です。採用するアニメーションライブラリの利用条件も個別に確認してください。

02 / REACT TO VIDEO

Reactで動画を組み立てる

同じ構成で商品名や数値を差し替える動画、字幕やデータを組み込むテンプレートにはRemotion。公式Agent Skillsを併用し、Reactの部品として画面を管理します。

Opus 5.5→Remotion Agent Skills→React + フレーム番号→Remotionの書き出し

動きの時間をそろえる

useCurrentFrame()のフレーム番号とFPSから、位置、透明度、色、カメラの状態を決めます。通常のWebの実時間アニメーションを使うと、プレビューと書き出しの状態がずれる場合があります。

3Dや既存アニメーションを足す

3Dは@remotion/three、Lottieは@remotion/lottieなど、Remotionのフレームへ連動する公式の統合が入口。すべてを一度に入れる必要はありません。

導入の入口

公式の空テンプレートを使う
npx create-video@latest --yes --blank motion-video
cd motion-video
npx remotion skills add
npm run dev

初稿はStudioで確認し、修正後に書き出します。公式スキルだけを既存プロジェクトに追加する場合はnpx skills add remotion-dev/skills。

Remotionは独自ライセンス。確認時点では、個人、従業員3人以下の営利組織、非営利組織等に無料枠があり、それ以外はCompany Licenseの確認が必要です。テンプレートの再配布と動画の制作も、同じ条件とは限りません。

03 / INTERACTIVE MOTION

触れる画面を動かす

クリック、ドラッグ、スクロールに反応する画面なら、MotionやGSAPをUIのコードへ組み込みます。Emil Kowalskiのスキルで、動く理由、速度、イージング、割り込みやすさを見直せます。

Opus 5.5 + 設計スキル→React / HTML→MotionまたはGSAP→Webで操作
表現入口選ぶときの視点
レイアウトの変化、ドラッグ、スプリングMotionReactとの接続、操作の途中で入力しても自然につながるか。
文字演出、複数要素の連動GSAP / Anime.js時刻と順番を管理できるか。GSAPの独自利用条件も確認。
立体、光、シェーダーThree.js / Fiber + Drei必要なGPU機能、Reactの有無、素材とカメラの扱い。
キャラクターの状態に応じた動きRive Runtimes制作済み.riv素材の有無、エディタ・素材・サービスの条件。

Webとして公開するときは、キーボード操作、prefers-reduced-motion、画面幅、重い描画の停止を確認。動画にも使いたいなら、入力に依存した動きを時刻から再現できる状態へ整理します。

04 / EXPLAIN WITH MOTION

仕組みを動きで伝える

数式や座標、アルゴリズムならManim Community。TypeScriptで場面と動きを組みたいならMotion Canvas。グラフはD3、地図や多くの点はdeck.glを必要に応じて選びます。

説明の構成表→Opus 5.5でコード化→Manim / Motion Canvas→書き出し + 内容の確認

解説では、動きの派手さより「どの段階で何が分かるか」が軸になります。数値の出典、単位、軸、数式を先に決め、文字を読み終わる時間を残します。地図API、フォント、LaTeXなどの依存は選んだ構成に合わせて用意します。

THE PRODUCTION LOOP

良い指示を、見直せる制作へ。

最初に素材、伝える内容、出力条件をそろえます。次に場面の役割を決めて実装し、画面と音を確認しながら修正する。この流れをスキルで共有できます。

01伝えることを決める

目的、視聴相手、必ず出す文、事実の出典、使う画像やロゴ。

02見た目と時間を決める

色、書体、画面サイズ、尺、FPS、場面の役割と切り替え。

03フレームを確認する

代表フレーム、境界、文字の切れ、重なり、素材の読み込み。

04通して視聴する

読みやすい速さ、つながり、音との同期、終わり方を確認して書き出す。

任意の時刻へ戻れる設計

HTMLの独立した制作ルートでは、seek(t)のような関数で、その時刻の全状態を計算します。フレーム番号をFPSで割って時刻へ変換し、描画が完了してから取得。途中へ飛んでも同じ画面へ戻れることが、反復や部分修正に役立ちます。

時間を基準にした状態の計算 / 独自の概念例
function stateAt(seconds) {
  const p = Math.max(0, Math.min(1, seconds / 0.8));
  const eased = 1 - Math.pow(1 - p, 3);
  return { opacity: eased, y: 40 * (1 - eased) };
}
// レンダラー側: seconds = frameNumber / fps
// ページ側: 状態を適用 → フォント・素材・描画完了 → 取得

乱数はseedを固定し、物理計算は任意時刻の状態を再現できる形にします。通常の時計、タイマー、未制御のCSS transitionに頼った進行は、フレーム取得とのずれにつながります。HyperFramesやRemotionでは各エンジンの時間制御に従います。
